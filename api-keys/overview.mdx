## What Are API Keys?

API keys authenticate requests from your backend to BillingOS. They are used with:

- **`@billingos/node`** — the Node.js SDK uses your `secretKey` for all server-side operations
- **Direct REST API calls** — pass the key in the `Authorization` header

---

## Creating an API Key

1. Navigate to **Settings → API Keys** in the dashboard.
2. Click **Create New Key**.
3. Give the key a descriptive name (e.g. "Production Backend", "Staging Server").
4. Click **Create**.
5. **Copy the key immediately** — it is only displayed once.

<Warning>
  After closing the creation dialog, the full key is never shown again. Store it securely in a secrets manager or `.env` file.
</Warning>

---

## Using Your API Key

### With the Node.js SDK

```typescript
import { BillingOS } from '@billingos/node';

const billing = new BillingOS({
  secretKey: process.env.BILLINGOS_SECRET_KEY!,
});
```

### With Direct REST Calls

```bash
curl https://api.billingos.io/v1/subscriptions \
  -H "Authorization: Bearer $BILLINGOS_SECRET_KEY"
```

## Best Practices

<AccordionGroup>
  <Accordion title="Never commit keys to source control">
    Store your `BILLINGOS_SECRET_KEY` in environment variables, not in code. Add `.env` to your `.gitignore`.
  </Accordion>
  <Accordion title="Use separate keys per environment">
    Create one key for production and a separate key for staging/development. This lets you rotate keys independently and limits the blast radius of a leak.
  </Accordion>
  <Accordion title="Rotate keys regularly">
    Periodically rotate your keys. Create a new key, update your deployment environment variables, then delete the old key.
  </Accordion>
  <Accordion title="Never expose keys client-side">
    Secret keys must only be used on your server. The React SDK uses short-lived session tokens (generated by your backend) for frontend authentication — not API keys.
  </Accordion>
</AccordionGroup>

---

## Revoking a Key

1. Navigate to **Settings → API Keys**.
2. Find the key you want to revoke.
3. Click **Revoke**.

Revoking a key is immediate — any requests using that key will fail instantly with a `401 Unauthorized` response.
