## What are webhooks?

Webhooks are HTTP callbacks that BillingOS sends to your server when events happen — like a subscription being created, a payment failing, or a customer upgrading their plan.

<Note>
  Webhook signature verification is coming soon. For now, you can start setting up your webhook endpoint and handling events.
</Note>

## Set up a webhook endpoint

Create an API route that receives webhook events:

```typescript app/api/webhooks/billingos/route.ts
export async function POST(request: Request) {
  const body = await request.json();
  const event = body.type;

  switch (event) {
    case "subscription.created":
      // A new subscription was created
      await handleNewSubscription(body.data);
      break;

    case "subscription.updated":
      // A subscription was changed (upgrade, downgrade, renewal)
      await handleSubscriptionUpdate(body.data);
      break;

    case "subscription.cancelled":
      // A subscription was cancelled
      await handleCancellation(body.data);
      break;

    case "payment.succeeded":
      // A payment was successful
      await handlePaymentSuccess(body.data);
      break;

    case "payment.failed":
      // A payment failed
      await handlePaymentFailure(body.data);
      break;

    case "invoice.created":
      // A new invoice was generated
      await handleInvoice(body.data);
      break;

    default:
      console.log(`Unhandled event: ${event}`);
  }

  return Response.json({ received: true });
}
```

## Common event types

| Event | When it fires |
|-------|--------------|
| `subscription.created` | New subscription started |
| `subscription.updated` | Plan changed, renewed, or modified |
| `subscription.cancelled` | Subscription cancelled |
| `payment.succeeded` | Payment processed successfully |
| `payment.failed` | Payment attempt failed |
| `invoice.created` | New invoice generated |
| `customer.created` | New customer record created |
| `entitlement.updated` | Feature access changed |

## Best practices

- **Return 200 quickly.** Process webhook events asynchronously if possible. Return a `200` status immediately, then handle the event in a background job.
- **Handle duplicates.** Webhooks may be delivered more than once. Use the event ID to deduplicate.
- **Verify signatures.** Once signature verification is available, always verify that webhooks are coming from BillingOS.
