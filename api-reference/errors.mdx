## Error response format

```json
{
  "error": {
    "message": "The requested resource was not found",
    "code": "NOT_FOUND",
    "details": {}
  }
}
```

## HTTP status codes

| Status | Code | Description |
|--------|------|-------------|
| `400` | `VALIDATION_ERROR` | Invalid request body or parameters |
| `401` | `UNAUTHORIZED` | Missing or invalid authentication token |
| `403` | `FORBIDDEN` | Token is valid but lacks permission for this action |
| `404` | `NOT_FOUND` | Requested resource doesn't exist |
| `409` | `CONFLICT` | Resource already exists or state conflict |
| `429` | `RATE_LIMIT` | Too many requests — slow down |
| `500` | `SERVER_ERROR` | Something went wrong on our end |

## Handling errors in the SDK

The React SDK throws typed errors you can catch:

```typescript
import { BillingOSError } from "@billingos/sdk";

try {
  await client.getSubscription("sub_invalid");
} catch (error) {
  if (error instanceof BillingOSError) {
    console.error(error.message);   // Human-readable message
    console.error(error.code);      // Error code
    console.error(error.status);    // HTTP status
  }
}
```

## Common errors

### "Session token expired"
The session token has expired. If using `sessionTokenUrl`, the SDK refreshes automatically. If using manual tokens, fetch a new one.

### "Customer not found"
The `externalUserId` used to create the session token doesn't match any customer. Make sure the user has an active subscription or has been created as a customer.

### "Rate limit exceeded"
You're sending too many requests. Wait and retry with exponential backoff.
